# 同步结算规则书：行动值、出牌、飞弹与死亡

- 规则版本：同步结算 v1，2026-10-21
- 适用：单人、多人手动池、多人自动池、幽灵、无动画模拟、回放。
- 状态：供战斗原型实现的规则基线；尚无运行中的战斗引擎验证。
- 上游：[战斗规则](rules.md)、各系卡表；下游：[AI 与执行器](ai.md)、联机与测试。
- 本文是“结算时序与冲突合并”的单一事实来源。卡牌的费用、数值及特有公式仍以卡表为准；旧文档的即时改状态、逐玩家结算、疲劳前生命决胜等口径与本文冲突时，以本文为准。

## 1. 核心原则

**同一时刻的双方行动，读取相同的公共起点，分别计算，再统一写入结果。玩家编号、网络到达顺序、动画命中先后不决定伤害。**

1. 行动值决定事件发生的时刻；阶段、出牌序号与伤害段决定同一时刻内的逻辑顺序。
2. 阶段之间有顺序，同一阶段内的对称行动没有先手方。
3. 卡牌内部保留“先支付后治疗、先叠层后毒伤、先获得盾后碎盾”等文字顺序。
4. 双方同一步卡牌都看不到对方本步尚未提交的变化；双方下一步都能看到已经提交的结果。
5. 发射时锁定攻击参数。该次发射新挂的毒，不追溯削弱同刻已发射的对方主弹或副弹。
6. 所有随机、取整、触发和死亡必须可重放；表现层只消费结果日志。

### 1.1 重要补充：伤害段不等于死亡检查点

同一次发射可能包含主弹、副弹、真伤副弹、风痕引爆和反伤。它们有内部顺序，但**整个同时发射组结束后才判定死亡**。否则一方的主弹先杀死对方，就可能取消对方同刻已经发出的副弹，重新引入偏差。

同理，一步卡牌内的多次毒伤及其已触发反应属于一个整体；不在这个整体中途取消另一方本步已经提交的牌。下一步牌、下一个全局阶段则必须等待死亡检查通过。

这是对讨论中“按批次检查死亡”的精确定义：本文的死亡批次指完整结算事务，而非每一小段伤害。

## 2. 术语与时间模型

| 术语 | 含义 |
|---|---|
| 时间点 t | 全局行动值；不受动画帧率影响 |
| 全局阶段 | 常规毒伤、毒层衰减、抽牌与出牌、疲劳、发射、到期 |
| 结算步 k | 同一抽牌阶段双方各自的第 k 张牌 |
| 快照 S | 本次事务开始时的只读公共状态 |
| 局部投影 | 在 S 的副本上，仅执行本方本张牌的文字顺序，用于计算条件与效果 |
| 效果意图 | 属性变化、伤害包、盾获得/消耗、治疗请求、毒层变化等；不是公共状态的直接写入 |
| 伤害波次 | 事务内部有顺序的一组伤害；双方同序号伤害同时结算 |
| 事务 | 原子死亡判定单位：一组常规毒伤、一次衰减结算、一步双方卡牌、一组疲劳、一次双方发射组或一组到期效果 |
| 反应 | 由已结算结果生成的反伤、返盾、潮汐记录等；带有来源和允许触发范围 |

一个事件定位键为 `(t, phase, cardStep, wave)`。键中不以玩家编号决定伤害先后。相同键的双方事件必须先收集完整，再统一处理。

## 3. 同一行动值的全局顺序

```text
收集 t 时刻全部到期事件
  1. 常规毒伤事务：双方毒伤及其蚀命/合法反应 → 死亡检查
  2. 毒层衰减事务：同时衰减/抵消/叠层 → 更新减益、计时 → 死亡检查
  3. 抽牌：双方完成抽牌、获得本次费用
     同时提交出牌队列
     第 1 步：双方第 1 张牌及其反应 → 死亡检查
     第 2 步：双方第 2 张牌及其反应 → 死亡检查
     ……
     未打出的牌回摸牌堆底，结束本次抽牌池
  4. 疲劳事务（达到疲劳起点且本次为抽牌阶段）→ 死亡检查
  5. 到期发射组：发射准备、主弹、副弹、引爆、反应、发射后清理 → 死亡检查
  6. 其他到期效果事务 → 死亡检查
推进至下一个有效事件时刻
```

- 仅处理本时刻实际到期的阶段。只有一方发射到期时，只生成该方发射；不把另一方的未来发射提前。
- 首发仍固定在 100，抽牌仍为 0、100、200……；0 时刻无毒层就不生成毒伤。
- 同刻毒伤先于毒层衰减，衰减先于抽牌和发射。衰减是独立事件，不必等到整百行动值。
- 任一事务结束后战斗终止，后续事务不再执行。在抽牌前被毒击败，不能靠本次抽牌治疗获救。
- 毒伤、疲劳等可引起反应或自动碎盾检查，但必须在其所属事务内完成，不插队到其他全局阶段。

## 4. 同步出牌协议

### 4.1 提交内容与可见性

每方提交一条有序队列：卡牌实例、选择的目标、已知的模式/选项、必要的检索选择方式。

- 提交前可以编辑自己的队列与预览自己能确定的效果；预览不是公共战斗状态。
- 双方提交前，不显示对手本次队列；禁止根据对方结算动画追加或改序。
- 自动策略与 AI 也必须先产出完整队列，不能读取另一方尚未公开的选择。
- 不允许人为插入空步骤。队列结束即放弃本次剩余出牌机会；0 费牌仍占一个合法步骤。
- 队列只引用本次抽牌池中的卡牌实例；同一实例本阶段最多打出一次。洗牌不把卡重新送回本次池，不可借此无限重打。
- 即时费用获得可支持队列后续卡；“下次抽牌多费/多抽”仅进入下次抽牌记录。

检索的随机候选只在该步骤执行时生成，不可在提交预览中提前泄露。手动玩家可在该步暂停后从合法候选中选择；此时只能完成该检索选择，不能修改已提交队列。双方都完成必要选择后再提交该步。自动模式使用预先提交的选择策略。随机结果与最终选择必须进日志。

### 4.2 费用与失败处理

逐步检查卡牌实例归属、是否已打出、目标合法性和当前费用。不存在提前借用后面返还费用的情况。

- 提交时能确定的非法队列直接拒绝，要求重新提交，不能偷偷删牌后执行。
- 运行中确实因规则状态变化变得非法的步骤，记录失败原因，不扣费、不移动牌，并结束该方本次剩余队列；另一方继续。
- 条件奖励未达成不等于非法出牌。例如火层不足仍可以打出卡牌，只是不获得条件奖励。
- 两方相同步骤均合法时，双方各扣费用，分别求值，然后合并；不能先结算一方，再用变化后的状态验证另一方。

### 4.3 单步执行

```text
S = 当前公共状态的不可变快照
planA = EvaluateCard(S, A 的第 k 张牌)
planB = EvaluateCard(S, B 的第 k 张牌)
result = ResolveTogether(S, planA, planB)
提交 result 与日志
完成限定反应、自动碎盾检查、死亡检查
存活时进入第 k+1 步
```

EvaluateCard 不可直接写入真实 BattleState。各自从 S 建立局部投影，只应用自己的牌，不应用对手本步的牌。

局部投影只用于求值，不能把其整份状态复制回公共状态。每次加攻、加层、消费、治疗都要有唯一操作ID，公共提交恰好执行一次；依赖真实伤害/有效治疗/实际消费量的奖励必须保留依赖，在对应结果确定后计算，不能先按预览值发奖励再重复发一次。

默认卡内顺序：支付费用 → 首次附魔/能力激活 → 卡表攻防加成 → 按文字顺序执行效果。卡文注明“打出前”则读取 S；其他“当前”读取执行到该句时的局部投影。显式“先/后”优先。

例：枯潮在自己的投影里先加毒、更新动态减益，再计算毒伤；对方同一步的伤害仍从自己的 S 投影计算，不会被这次新毒改变。下一步双方才共同读取新的减益。

**同一步增加防御也不会倒过来减少对手已经从 S 计算的本步伤害；护盾与治疗则按下节的资源承接规则生效。** 这不是玩家先后手，是属性计算与资源结算的统一约定。

## 5. 效果合并与伤害承接

### 5.1 属性、状态与资源必须分开存储

```text
最终攻击 = max(0, 基础攻击 + 永久攻击增减 + 临时攻击修正 - 动态毒减攻) × 已激活的最终攻击倍率
最终防御 = max(0, 基础防御 + 永久防御增减 + 临时防御修正 - 动态毒减防) × 已激活的最终防御倍率
```

- 同步加减攻防合并为增量，不用“最后写入的整个人物对象”覆盖另一方结果。
- 毒层变化只更新毒层，再推导毒减攻/减防；不要通过反复扣除、加回当前攻击实现减益。
- 相同属性的固定加减先汇总，乘法按卡表规则组合；无序容器迭代顺序不得影响取整。
- “防御归零”、消耗全部资源、替换持续效果等不是普通增量，必须有独立操作类型及明确作用范围，不能作为负无穷增量处理。

### 5.2 普通盾、免衰减盾与临时盾

同一步普通获盾先汇总，旧盾只衰减一次；不同出牌步独立衰减。盾是双方同一步伤害的承接资源，**先落实本步获盾，再吸收本步伤害**。

无主动消耗时：

```text
若本步至少有一次正数普通获盾：
  Snew = ceil(Sold × retention) + 普通获盾总和 + 免衰减获盾总和 + 临时获盾总和
否则：
  Snew = Sold + 免衰减获盾总和 + 临时获盾总和
```

- retention 默认 0.75；已生效的不坏壁垒按 0.8。新打出的不坏壁垒对其本次获盾使用 0.8；重复激活不累乘为 0.64。
- 盾脉等免衰减获盾不单独触发旧盾衰减，也不取消其他普通获盾触发的衰减。
- 同一步双方都有给予某玩家护盾的效果，也按接收者统一合并。不能按来源玩家排序后连衰减两次。
- 原80盾，同一步获得100与20普通盾，结果为180盾；分成两步先100后20，则为140盾。
- 获盾带条件奖励时，“当前盾”在本牌局部投影里判断；不因对方同一步赠盾而重新触发奖励。

有主动消耗/削盾时：在局部投影中记录消费的**绝对盾量**与合法来源，不把“清空盾”作为未来执行的无条件 setter。公共合并先得到获盾结果，再扣这些已承诺数量，扣除不超过可用盾；消耗、百分比削盾均不触发敌方破盾反应。伤害或返还必须以实际合法消费量为依据。对方同一步额外送来的盾不被本牌“消耗全部”自动吞掉。

若未来出现双方同一步争用同一有限盾池并各自转伤的机制，必须为该机制补充对称分配规则后才可上线，不能让先遍历者先拿走资源。

临时盾仍与普通盾共用当前盾量，但额外记录“下次发射组结束后清空全部盾”的标记。该清空发生在发射组所有伤害和反应完成后，不能在主弹后、副弹前执行；清空不是被敌方击破，不触发破盾反应。

### 5.3 伤害包与顺序

伤害包至少携带来源、目标、类型、段序号、锁定基数、穿盾比例、防御处理是否已完成、允许触发的效果及父事件编号。

- 不同的主弹/副弹分别按各自公式计算防御，不能把多段先合起来只减一次防御。
- 一张牌说“连续两次毒伤”，产生两次有序毒伤；每次将基础毒伤与蚀命追加段合并求和，只减一次防御，再统一过盾。
- 同一步双方各自第1段同时结算，再结算双方第2段；某方没有对应段则为空。段序号由卡内文字/发射规则确定，不由玩家编号决定。
- “下一次受伤”的易伤与一次性减伤只作用于第一段普通飞弹伤害；实际伤害为0的空段不消耗。毒伤、碎盾伤害、真实伤害不受易伤/减伤影响；支付生命、疲劳不消耗这些标记。
- 旧易伤可影响本步第一段飞弹伤害；本步新施加的易伤在步末生效，不修改对方本步已生成伤害。卡文若明确自身“先施加再伤害”，允许在该牌自己的投影内应用，并只消耗一次。
- 对某个目标，同一波次若需要处理多段，必须使用明确的局部段序号。未来新增多来源真正无序打同一目标的机制时，须先定义资源与触发归属，不能回退到玩家ID优先。

护盾吸收与生命损失逐波推进，因此后段能打进前段已经击破的盾；但后段仍使用原先锁定的攻击/防御计算参数。

普通穿盾伤害先按卡表比例分成直接生命部分与过盾部分；比例限制在0–100%，不产生负的过盾伤害。对盾增伤只放大盾消耗，不把仅针对护盾的放大额转为生命溢出。若过盾基数为 b、对盾倍率为 m、现有盾为 s，则盾吸收的基数为 min(b,s/m)，扣盾量为该值×m，剩余基数才扣生命；按统一精度计算到最后再取整。

### 5.4 治疗、生命支付与过量伤害

- 卡内先支付后治疗照文字顺序执行；支付不能因同一步对手尚未结算的伤害而临时变小。支付不是伤害，保持卡表“不低于1”等约束。
- 直接治疗在承受对方本步伤害前确定有效量：只填补当时已有缺血，不预存给即将受到的伤害。多个直接治疗按卡内顺序处理，共享最大生命容量。
- 将本步获盾和直接治疗落实后，逐波路由伤害；同一波双方同时路由，然后根据实际生命伤害产生吸血请求，再同时结算吸血。
- 实际生命伤害不包含打盾量、过量伤害；最多计至该段开始时目标剩余的正生命。过量伤害保留在事务临时生命中，不因提前夹到0而被抹掉。
- 吸血的有效治疗受最大生命限制，可救回本事务内尚未正式判死的角色；不能救回上一事务已判死的角色。吸血不重新增加本波已经计算的实际伤害上限，禁止伤害与回血相互回算。
- 事务内生命允许为负，最终判死前再统一写出结果。支付生命的可支付基数用 max(0, 临时生命)，不能从负血制造资源。
- 每笔有效治疗才记录潮汐；本次发射已经消耗的潮汐不会重新吸收这笔新潮汐，新潮汐留给下次发射。潮汐回廊的治疗按卡文禁止记录。

例：当前100/1000生命，同步直接治疗50、受到120生命伤害，结束剩30；若当前1000/1000，同样治疗50被浪费，受120伤害后剩880。若100生命受到180伤害、该波吸血50，结果为-30，不能先夹到0再回到50。

## 6. 同时发射：一次锁定，多段结算

### 6.1 发射准备与快照

所有本时刻发射者一起进入准备，先从同一状态生成准备效果，再同时提交：

1. 支付血潮生命；记录并入该发飞弹的增伤量。
2. 结算土附魔发射获盾；大地之握在该获盾之后消耗盾，记录实际消耗量。
3. 扣除本次使用的余烬、潮汐和限次增益，记录其数值；递增本次主飞弹计数。
4. 建立发射快照 L，锁定本次所有段的攻击、目标防御、层数、倍率、穿透、第三次资格及攻击间隔修正。

没有到期发射的一方不支付血潮、不获得土发射盾、不消耗下一发效果。双方的准备一起提交，任何一方都不能因程序先执行而看到另一方不完整的准备状态。

### 6.2 发射内部顺序

```text
双方主飞弹（含并入主弹的潮汐、追击、盾转伤、固定加伤、血潮增伤）
→ 双方第1段加成副弹
→ 双方第2段加成副弹……
→ 双方第三次主飞弹对应的真伤副弹（如有）
→ 双方风痕引爆（如有）
→ 统一反应窗口：反伤 → 合法返盾/状态记录 → 自动碎盾检查
→ 发射后临时盾清空、下一发排程
→ 死亡检查
```

- 加成副弹按产生它们的出牌步骤排序，同一牌内按文字顺序。此顺序在提交后固定。
- 主弹和加成副弹的命中按波次提交风痕；风痕引爆因此能读取本次主弹与副弹刚叠的风痕，使用 L 中攻击力计算。
- 毒层、永久属性、实际治疗和新潮汐在每波后更新公共状态，供后续合法触发与事务结束后行动使用；它们不改写 L。
- 第三次真伤副弹不额外计一次主弹，不叠毒，不叠风痕，不触发其他系命中效果，按现有卡文执行。
- 主弹实际生命伤害>0才使毒层+1；并入主弹的潮汐、追击、盾转伤、血潮增伤等只构成一次主弹命中。加成副弹/真伤副弹不额外叠毒。
- 余烬之核按主飞弹完成防御、飞弹易伤与减伤后的结算伤害（含打盾部分）判断阈值；不把各副弹拼在一起凑阈值。新余烬不补回本发已消耗的余烬。
- 真正生效的盾量、一次性易伤/减伤标记仍按波次更新，不把整组盾状态冻结在发射开始。

### 6.3 下一次发射时刻

下一次发射时间 = t + 本次发射快照锁定的间隔。先固定加减，后乘法，最后向上取整并至少为1。只消耗实际用于本次发射的限次修正。发射中生成的未来间隔效果留给下一发，不重排已经生成的飞弹。

已排程的发射不因抽牌阶段新获得减间隔而立刻提前；新间隔在该发之后使用，保持原有规则。

## 7. 毒、蚀命、衰减与同刻事件

- 毒层为0不产生任何常规/额外毒伤或蚀命伤害，不执行公式中的保底1。
- 常规毒伤：双方从共同快照计算基础毒伤；各自蚀命按同一毒伤事件锁定的层数、防御计算附加量，不因段间对方状态变化重新定价。
- 蚀命的百分比生命伤害并入同一次基本毒伤，合并求和后只扣一次50%当前防御，再统一过盾；不是真实伤害，不是每层/每段独立扣防。蚀命不触发自己。
- 毒爆使用本牌投影里的消耗前层数计算，伤害后扣层；不触发蚀命。多个有序引爆读取各自步骤实际剩余层数，不能重复消费。
- 任何方式实际增加毒层，都按增加后总层数重置衰减计时，包括枯潮、速腐、固毒。只触发毒伤、不加层，不重置计时。
- 衰减的基础间隔为 floor(200/毒层)，延长加法汇总后乘算并向上取整；最终至少1行动值，0层取消计时。
- 衰减到期先判断固毒等抵消次数；若抵消并加层，则消耗1次保护，按新层数重新排程。蚀骨保留最后1层时，不生成无效减层/转攻触发，也不在同一时刻无限重试。
- 毒层变化后立即推导动态减益，但已生成的对手伤害包或发射快照不被追溯修改。

计时实现必须使用版本号：每次重排增长 poisonTimerGeneration。旧到期事件版本不匹配则丢弃，不得执行“已经被重置”的衰减。

## 8. 反伤、返盾、主动碎盾与自动斩杀

### 8.1 有界反应窗口

- 一次事务的直接伤害阶段记录破盾、吸收量等事实；反伤在该事务的反应窗口统一生成，而非在扣盾函数里递归执行。
- 碎盾前护盾量指造成该次破盾伤害到来前的实际剩余盾，不是历史最高盾。护盾从正数降到0才算被击破；原盾为0时不能重复破盾。
- 不周山反伤需要有效专精；壁垒之心替换普通反应反伤判定，不同时再结算一份不周山基础反伤。
- 吸收量使用减伤后的实际扣盾量。壁垒之心“每次飞弹一次”按明确的 missileId 去重，不能按多个伤害成分重复反伤。
- 反伤伤害可以被盾吸收、击破盾、扣生命，但标记 canTriggerRetaliation=false；不触发反伤、破盾返盾或新的自动碎盾连锁。
- 反伤的层数、系数和目标防御使用导致它产生的直接伤害事件所记录的参数；反伤基数使用该事件的碎盾前盾量/实际吸收量。不能因窗口延后而重新读取被后续毒层修改的参数。自动斩杀是例外，按检查窗口的新快照计算。
- 直接伤害触发的返盾在反伤完成后统一落实；返盾不回溯保护已经承受的副弹。主动消费、到期清空、百分比削盾不触发“被敌方伤害击碎”的返盾。
- 同时被打到临时负血者，其本事务已经合法记录的反伤仍结算；不能按哪方先暂时掉至0来取消反伤。

### 8.2 自动碎盾斩杀

旧文案中的“每当盾/层数/敌方生命等变化立即检查”统一解释为：标记需要检查，在公共结果提交后的自动检查窗口处理，不在某一玩家的局部投影里提前宣布胜利。

- 每步卡牌、每次常规毒伤、衰减、疲劳、发射、到期事务的反应窗口末尾，使用共同最新快照同时检查双方候选。
- 只有检查时生命>0、护盾>0、专精有效的角色能新发起自动碎盾。目标生命已≤0时不再补一次斩杀。
- 判定使用当时的实际盾、目标防御及穿透分配；满足条件才生成消费护盾与碎盾伤害。双方都满足则一起执行，不能先斩杀一方后取消另一方。
- 自动碎盾伤害不触发反伤、返盾或再次自动碎盾。本窗口最多一轮，不使用“while直到无人能斩杀”的递归。
- 自动碎盾成功时按既有设计让自身当前防御归零；本实现以清空当时基础/永久/临时正防御贡献实现，保留负修正和毒修正，未来新加防可重新积累。普通敌方破盾和主动碎盾牌不自动附带防御归零，除非卡文另有说明。

这个窗口约定会让同一步新盾与治疗都先落实再判断斩杀，避免以回调先后决定能否救下目标。

## 9. 死亡与赛事结果

死亡检查只发生在完整事务结束处。某波临时生命≤0不取消同一事务里已经提交的行动、已生成的飞弹段或合法反应；但不能新增自由选择的行动。

每次死亡检查先根据同一事务结束状态判断双方是否满足「时光倒流」等明确的复活效果；满足条件的双方同时恢复，再按下表判断胜负。时光倒流保留打出后 200 行动值内、每场一次的限制，完整恢复卡文指定的记录状态，不回滚全局行动值或对方状态。普通治疗不能替代这一步复活。下表中的生命均指合法复活结算后的生命。

| 事务结束状态 | 结果 |
|---|---|
| 双方生命>0 | 战斗继续 |
| 一方生命≤0 | 该方失败，另一方获胜 |
| 双方生命≤0 | 同时击败；双方各扣本轮基础赛事伤害，不计算赢家剩余生命项 |

- 同时击败规则适用于飞弹、卡牌毒伤、反伤和疲劳，不按疲劳前生命大小、先后发送或玩家编号决胜。
- 赢家剩余生命使用事务完成后的生命值，盾不计入赛事扣血。
- 战斗结束取消所有后续事件与未执行队列；已生成结果日志保留用于回放。
- 幽灵对局若同时击败，只扣存活玩家本轮基础赛事伤害；幽灵不获得赛事血量，也不影响其他玩家。

## 10. 程序结构与执行约束

### 10.1 建议的数据边界

| 类型 | 责任 |
|---|---|
| BattleState | 已提交状态；唯一写入点是提交器 |
| BattleSnapshot | 不可变读模型；包含版本、时间、属性组成、资源和触发状态 |
| SubmittedQueue | 本次抽牌阶段的卡牌实例与决策，带锁定版本 |
| EffectPlan | 卡内有序操作与条件依赖；不含公共状态写入 |
| DamagePacket | 基数、类型、锁定参数、段序号、来源与触发许可 |
| ResolutionTransaction | 收集双方计划，处理波次、合并资源与限定反应 |
| TriggerRecord | 已发生事实、源事件、去重键、允许的后继触发 |
| EventQueue | 下一时刻事件，支持取消/版本失效 |
| BattleLog | 每次输入、状态摘要、结果与随机选择，可独立重放 |

不要把 Entity.TakeDamage() 写成会立即反伤、立即治疗、立即结束战斗的递归函数。它应只参与受控事务中的资源路由，返回事实记录。

### 10.2 调度伪代码

```text
while not battle.ended:
    t = events.nextValidTime()
    due = events.takeAllAt(t)
    for phase in GLOBAL_PHASE_ORDER:
        if phase == DRAW:
            drawForAllDuePlayers()
            queues = await collectAndLockQueues()
            for k in range(maxQueueLength):
                snapshot = freeze(battle)
                plans = evaluateBothWithoutPublicWrites(snapshot, queues, k)
                commit(resolveTransaction(snapshot, plans))
                if resolveRevivalThenCheckDeath(): break
        else:
            snapshot = freeze(battle)
            plans = buildDuePlans(snapshot, due, phase)
            commit(resolveTransaction(snapshot, plans))
            if resolveRevivalThenCheckDeath(): break
        if battle.ended: break
```

ResolveTransaction 内部：资源准备 → 有序伤害波次（双方先算后写）→ 每波有效治疗/命中事实 → 有界反应 → 自动碎盾 → 清理。Evaluate 可以并行，也可以顺序执行；只要读同一快照、没有公共写入，结果必须一致。

### 10.3 确定性、网络与随机

- 使用整数或明确精度的定点/有理数计算，不依赖帧时间或平台浮点误差；潮汐按卡表保留内部小数。伤害段边界统一取整，不在每个加成上任意重复取整。
- 非负护盾与计时在最终边界取整；穿透比例夹到0–100%；攻击间隔与衰减至少1。说明里的显式 floor/ceil 优先。
- 随机使用战斗种子及稳定的玩家随机流/事件子流；交换座位时连同对应随机流一起交换。不能因为先遍历A就先消耗公共随机流。
- 到期事件即使已被收集到 due，在进入对应阶段时仍要再次核验版本与战斗状态；前面阶段重置过计时的旧衰减事件不得继续执行。
- 同一伤害波先完整计算双方，随后一次提交；日志打印顺序可以排序，但排序不得改变状态。
- 联机由权威端验证队列和状态版本；迟到或重发提交用 submissionId 去重，不重复扣费或出牌。超时托管作为独立房间策略，不改变伤害规则。
- 动画不回写战斗状态，不用碰撞到达时刻决定伤害；需要先表现一方时也只能播放已确定的同步结果。
- 发现超出规则允许的反应链，报规则错误并保存快照，不能静默丢弃后半段伤害或随机选胜者。

### 10.4 必记日志

记录规则版本、卡表版本/哈希、战斗种子、队列提交、检索随机候选与选择、t/phase/step/wave、快照版本、卡实例、局部条件判断、锁定攻击/防御、公式输入、最终伤害、盾吸收、有效生命伤害、治疗及溢出、毒层/计时版本、触发父子关系、消费与返还、死亡检查结果。

只记录动画和最终血量不足以定位同步结算错误。

## 12. 适用边界与待定卡文

本规则确定先后与同步方式，不替代全卡数值模拟。旧卡文仍有独立语义缺口时，必须先补齐卡定义，不能在执行器里偷偷选一种解释。

本次为使原型有一致行为而补齐的规则选择包括：整组发射末尾判死、直接治疗不预存、同一步普通获盾只衰减一次、反伤不递归、自动斩杀在窗口统一检查，以及自动碎盾的防御归零作用范围。这些会影响数值，应随本规则版本一起进入模拟，不能当作纯性能重构忽略。

当前至少需要确认：毒爆传奇的“每次减少+2攻”按事件还是按层；回震岩甲等持久返盾效果重复打出时是叠加触发次数、数值还是刷新。它们不影响本文基础同步结构，但在确定前不能把相关完整对局结果当成平衡依据。

实现顺序建议：先做纯攻防/盾/治疗的双边事务与S01–S11，再做出牌队列与随机，最后加入毒、复合飞弹、反伤和自动斩杀。始终以同一执行器供手动、AI、无动画模拟和回放使用。
