# 构筑候选审计与显示设置（2026-10-26）

规则来源：`releases/deckbuilding-v1.0/README.md`、`probabilities.json`、`economy.json`、`pool-counts.json`。用户后续修订优先：所有传奇禁止主动删除，主系不能减至三张以下。此次只修客户端实现，没有修改冻结的概率、份数、卡牌或训练模型。

## 发现与修正

此前全量客户端沿用了切片的直接随机选卡，没有按轮次抽稀有度；保底只尝试展示一张路线；刷新也从所有稀有度中直接选牌。另有直接从未展示库存选择路线的入口，以及非路线传奇替换为路线时错误使用两点价格的路径。主系最低三张检查曾把赠送专精牌算作附魔，现已在规则核心和AI合法动作中共同排除。

现在全量客户端使用独立的 `Core/Draft/FrozenDraftRules.cs` 和 `DraftOfferAllocator.cs`。旧切片池仅用于兼容历史测试，继续使用旧生成器；正式客户端始终加载全量池和冻结配置。

| 检查项 | 客户端实现 |
|---|---|
| 第1—7轮及8轮以后，两面各自概率 | 从冻结JSON读取；每个位置只抽一次，不额外重抽或升档 |
| 第1轮/第6轮以前限制 | 第1轮无史诗，第6轮以前无传奇，由模板保证 |
| 2/6/7轮概率硬上限 | 按满8+8位置解析计算至少一张的概率；不是每面卡牌数量上限 |
| 8/10/12轮首面 | 索引0/1/2固定传奇，前两位优先路线；先按全场路线库存联合分配可行元素，避免可解决的元素拥挤；专精前可来自全体未持有且可用路线 |
| 保底轮刷新 | 从未购买索引中最低稀有度者等概率挑一位升传奇；已有自然传奇也执行 |
| 预抽与分配 | 所有人两面模板先完成；首面通过全场最小费用流联合分配，刷新按权威命令顺序分配 |
| 匹配优先级 | 保护传奇保底、减少稀有度降级，再减少类型/元素偏差；缺货只向下替补，仍无则空缺 |
| 非传奇抽样 | 合法档位内按剩余份数的指数随机成本参与联合匹配；不设逐卡偏置 |
| 专精前 | 2/3/4张附魔软目标20%/60%/20%，五系均权，每面同元素最多一张 |
| 专精前刷新 | 第一面买过的每个元素独立10%准入；不因缺配额而强行放行 |
| 专精后 | 只展示本系和通用；本系65%软目标，部分刷新按启用位置比例随机取整 |
| 传奇类型 | 6—8轮与9轮后分别读取冻结类型权重；前三位保底优先路线目标 |
| 名称与实体去重 | 同面不重名、不展示已持有名；玩家本轮两面传奇不重名；共享传奇每份每轮至多展示一次 |
| 传奇释放 | 释放恢复空闲库存，不恢复本轮未展示预算；通用传奇两份可以分别展示给不同玩家 |
| 刷新事务 | 保留已购原索引，释放未购旧候选，使用库存/RNG副本规划，成功后统一扣1点并提交；拒绝不改状态 |
| 空位与跳过 | 空缺保留原始模板索引；跳过不等于购买，刷新仍可启用；全部买完拒绝刷新 |
| 买卡与替换 | 稀有度价格1/2/3/4；同专精已有路线换路线2点；最多3传奇、1路线；替换显式选择旧卡 |
| 免费购买 | 1—3轮首普通，4—6轮首普通或稀有；两面共用一次，刷新不重置 |
| 专精与广播 | 第三张同系附魔立即赠专精牌；路线购买/替换同样生成规则变更事件 |
| 删除与回池 | 分轮限制、第二次收费、至少8张、主系至少3张、所有传奇/专精禁止删除；删除/替换下轮回池 |
| 轮间经济 | 基础收入2/3/4、继承最多2、每3连胜/连败下轮+1，双死中断 |
| 信息边界 | 模板、库存、未展示传奇预算和权威RNG只在规则核心；AI观测不包含这些字段 |

`DraftState.FirstRarities/RefreshRarities`、`ShownLegendaryIds`、`AllocationAudit` 与 `MatchState.UnseenLegendaryCopies` 都进入状态哈希和恢复快照。`AllocationAudit`记录目标、刷新保底索引、稀有度降级、类型/元素偏差、空缺，不把库存不足伪装成保底成功。

联合匹配的最终边际分布不等于独立逐卡抽样；元素数量与传奇类型是库存和合法性约束下的软目标。传奇实体用“按卡名剩余未展示份数”记账：同名实体可互换，不需要向客户端暴露物理副本ID。

## 验证入口

- `DraftAllocationRegression`：20轮×12种子，共240组，每组四人首面、购买、刷新与恢复重放；检查稀有度、保底位置、元素、传奇展示预算、库存守恒、拒绝原子性和哈希一致性。另有全场稀缺牌重分配、空池、元素准入及专精测试。
- `DraftEconomyRegression`：逐轮免费资格、删除、收费、延迟归还、研习收入/继承/连胜败、自动专精、主系保护、禁止库存直接选路线、全部买完禁止刷新。
- `FullTournamentRegression`：真实训练AI完整多轮赛事，两个种子各重复两次；构筑与结算检查库存守恒；保存最终状态哈希与事件摘要。
- `AiPrivacyRegression`、`AiAsyncFlowRunner`：隐藏信息变更不影响AI观测/决策，以及异步客户端流程。
- `DraftAuditRunner.tscn`：单独运行构筑专项与Godot显示设置对话框检查；一键回归脚本已包含此入口。
- 输出：工作区 `runtime/draft-rules-audit.json`、`runtime/regressions/trained-ai/summary.json`。

旧基线另存 `Data/Regression/trained-ai-baselines.pre-draft-audit.json`。候选生成和快照字段修正会使旧赛事及旧切片状态哈希改变；只在规则专项检查和相同种子重复重放一致后更新正式基线。

满位置概率解析结果：第2轮首面至少一史诗14.9237%，两面36.0225%；第6轮两面至少一传奇9.5458%，第7轮18.2343%，分别低于20%/50%/10%/20%的上限。这些值仅针对稀有度模板；合法性与库存可能进一步降低实际展示概率。

最终验收通过：构筑240组与逐轮经济检查、253张卡牌506条执行路径、253个牌面档案、AI公开信息边界、完整客户端启动及显示设置。种子20261024两次均18轮结束，种子20261026两次均15轮结束，最终状态与事件摘要逐一相同；正式基线已保存，且核对了所有回放源码指纹。两轮异步客户端流程通过，最高AI轮询耗时18.86ms。测试通过证明上述回归覆盖内行为一致，不代表穷尽所有可能对局。

## 显示设置

`project.godot`设定1920×1080设计视口、1920×1080默认窗口、可调整窗口大小，沿用canvas_items缩放与expand布局。`Application/DisplayPreferences`只处理本机显示偏好，不进入赛事状态与随机流。

客户端顶部“显示设置”可选1280×720、1600×900、1920×1080、2560×1440、3840×2160及全屏。全屏采用显示器当前分辨率；保存的窗口分辨率用于退出全屏后恢复。首次启动默认1920×1080窗口；应用后写入`user://display.cfg`，下次启动恢复。Windows通常位于`%APPDATA%/Godot/app_userdata/Magicians!/display.cfg`。设置文件缺失、损坏或尺寸越界时回退默认值；窗口最小960×540。

## 玩家战斗、后台对局与本轮代理

玩家场进入战斗后立即可以操作，另一组AI对战在后台推进。推理请求按参赛者串行，不再跨参赛者共用推理等待锁；两场战斗的命令仍只在Godot线程提交给权威执行器。玩家场优先轮询，后台对局的事件不进入玩家战斗日志，也不触发无关卡面重建。若玩家先结束，保留玩家场结果和日志，后台对局完成后统一进入轮次结算。

`Application/CombatPlayerView`只向玩家界面提供自己的当前抽牌池及双方公开数值，不提供对手的抽牌池、牌堆顺序或待提交指令。对手已打出的牌仍是公开事件；抽牌与检索选择事件不公开。每轮清空上一轮战斗日志，后台AI对局不占用该日志。

“本轮战斗由AI代理”在玩家战斗结束前可用，包括已经提交当前操作、等待同步结算的时刻。开启不撤销已提交操作，不改变玩家身份；之后由训练好的战斗AI读取本方完整牌组组成、当前可用牌、弃牌、已出牌和对手公开状态，自动出牌、检索和结束窗口。手动战斗命令在会话边界拒绝，下一轮恢复手动构筑与战斗；代理不接管构筑，也不读取对手私有牌组或未来抽牌顺序。

回归入口`CombatClientFlowRunner.tscn`使用真实训练AI完成两轮，检查玩家未操作时另一组对局继续推进、后台事件隔离、对手抽牌/检索隐藏、公开出牌保留、中途代理、手动命令原子拒绝、整套牌组观测及下一轮恢复。已加入`tools/run_client_regressions.ps1`。本次构建零警告零错误；新回归通过，最高主线程AI轮询耗时17.80ms，原异步流程回归通过（21.68ms）。这些耗时是本机此次测试观测值。

## 逐轮复盘、构筑广播与删牌画廊（2026-10-26）

`GameSession`按轮次和对局保存权威提交成功后产生的全部`CardPlayed`事件以及最终赛果，手动与AI走同一记录入口，轮间不清空。只存已公开打出的卡，不保存或揭示对手未出的手牌、抽牌顺序和待提交指令。玩家赛事生命耗尽后或赛事结束时，主界面自动展示复盘；最终结算仅剩至多一名存活者时自动完成赛事结束阶段。可按轮次和已完成对局筛选，查看行动值、同步步骤及双方每步出牌；点选记录显示该步完整卡面。可以返回赛事继续查看剩余对局。

构筑阶段显示独立可滚动广播区，读取所有玩家的`Specialization`、`Route`、`ReplaceRoute`公开事件，包含轮次、玩家及具体专精/路线；不将删牌、刷新候选等私有信息混入广播。稀有度文字分别使用普通浅灰、稀有蓝、史诗紫、传奇金、专精绿。

删牌入口收束为单个“删牌（本轮已删除N张）”按钮。弹窗包含整套牌组每一张实体的完整卡面和下方“删除”按钮；不合法牌仍展示，但删除按钮禁用。删除通过现有命令及实例ID执行，立即刷新数量和画廊，不改变价格、轮次限制、至少8张、主系至少3张、禁止删除传奇/专精和下轮回池规则。

路线生成的用户修订已在`DraftOfferAllocator`硬约束：持有路线的玩家，第10/12轮各最多新展示1张路线传奇，首面和刷新共用；根据已有`ShownLegendaryIds`扣除预算。其他传奇位置不再强制路线，并禁止匹配器以路线回退补齐。未持有路线者与第8轮保持原生成目标，原稀有度模板、三传奇保底和刷新保底不变。该修订不改模型、卡牌或经济。

`DraftUiRevisionRunner.tscn`验证80组路线持有者（10/12轮、五系、八种子）、四人专精/路线/替换广播、稀有度标签颜色、删牌弹窗全牌展示、确切实体删除、删除计数和8张保护、淘汰/结束自动复盘；已加入一键回归脚本。原240组构筑审计通过。252张卡504条执行路径与252卡面通过。全赛事回归额外核对所有轮次/对局和已打出卡事件均被复盘记录保存：两个种子分别16/14轮，各重复两次状态和事件摘要一致，记录的源码指纹一致；新基线固定，旧基线保留为trained-ai-baselines.pre-route-cap.json。真实AI异步/代理与后台事件隔离回归通过，最高轮询15.62ms。Godot实际窗口已核对删牌画廊和复盘表格/完整卡面，正常退出。

## 战斗状态、附魔标记与构筑隔离（2026-10-26）

## 启动界面与淘汰后观战（2026-10-26）

Boot现在只加载主菜单，不会自动创建赛事。主菜单提供“开始单人赛事”和“退出游戏”；点击开始后才创建`GameSession`、进入第一轮构筑。赛事结束或玩家淘汰后，赛事页提供“逐轮出牌复盘”“观看 AI 对局直到冠军”“重新开始一局”“退出游戏”。

玩家淘汰后选择观战会进入会话级自动推进：后续AI构筑使用独立推理进程，AI战斗沿用后台权威协调器，轮次结算自动进入下一轮，直到`Finished`并显示最终冠军。观战不改变已经记录的战斗日志或赛事结果；重新开始会释放旧会话并重新回到第一轮，退出直接关闭Godot窗口。

`MainMenuFlowRunner`验证启动门控、开始按钮、重开/退出控件和观战开关；`SpectatorFlowRunner`使用1点赛事生命的完整赛事验证玩家淘汰后自动观战至冠军（本次结果为第2轮结束）。实际菜单截图见`runtime/main-menu-preview.png`。


## 最终伤害公式审计（2026-10-26）

逐段复查了普通主弹/副弹、毒伤、碎盾反应、自动护盾爆发、风痕与真伤副弹、余烬、潮汐、血潮、目标易伤/减伤、护盾分配、疲劳和死亡检查。按用户确认的分区重新固定：普通增伤区在“基础攻击/倍率减有效防御”之后；潮汐值、血潮支付收益和路线/卡牌的直接飞弹加伤进入该区；火层最终倍率只作用于对手实际生命伤害，不放大护盾吸收；余烬保持主弹专属倍率；毒伤使用50%防御；护盾穿透与生命段分离；疲劳按文档使用向上取整并保留1点下限。

新增`DamageFormulaRegression`覆盖基础减防、穿透、毒伤、护盾分配、碎盾分配和疲劳取整；全卡504条执行路径、卡面252张、Python规则校验、客户端回归和两个固定种子各重复两次均通过。由于公式和疲劳取整修订，固定种子基线已更新并保留旧基线`trained-ai-baselines.pre-damage-audit.json`；最新状态/事件摘要和源码指纹记录在`Data/Regression/trained-ai-baselines.json`。
