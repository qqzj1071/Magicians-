# v1.2 新结算内核验收

当前正式入口 tools/sim_v12/tournament.py 默认使用 LockedBattle。客户端、v1.1冻结引擎和卡牌不在本次修改范围；verify_v11.py通过。

本次发现并修正的问题：

1. 土系原来只在整卡末尾检查斩杀，遗漏卡内获盾/耗盾、支付后回复前的窗口。现由每次敌方生命/自身盾量真实变化触发，普通同步伤害先共同提交；激活土专精也检查现有盾。
2. 原实验序列会因真实状态改变而缺牌、少抽或费用失效。现锁定具体实例、选择、随机结果和费用，仅重放已经正式到达的前缀；不复制规划治疗/潮汐等战斗资源。
3. 同位耗毒与净化可能重复统计移除，或删除同位新毒。现在分别确认共同快照，真实旧毒只扣一次，新毒保留，毒爆成长只计真实变化。
4. 同位重复施加相同减益可能被净化误删。现在减益带来源行为标识，仅清位次开始已有实例。
5. 新内核重放曾丢失碎岳之心的耗盾加伤；保留 Python 已加载的可变容器身份后修正，并重跑既有数值回归。
6. 即时水伤曾读取对方同位增加后的防御；现在锁定共同位次快照的防御。
7. 自动斩杀队列曾先处理一个座位，可能取消另一方同时符合条件的碎盾。现在从同一真实状态共同确认、共同消耗、同步伤害，允许双死；有直接回归。
8. 复活净化与同位普通净化的预算边界需要区分。复活清除当前真实毒层，包括本位新增毒；不受普通卡牌只清Ck旧毒的上限限制。

验证包括全部239张低/高资源环境执行矩阵、原有59项数值/牌区/构筑回归接入新内核、锁定抽牌和费用、不补造潮汐、随机操作一致、护命/已打复活/未打复活、死亡截断与牌区前缀、毒层去重、新减益保留、耗盾削盾比例分配，以及卡内插入斩杀。顶层84项测试通过，其中一项再次执行原有59项数值回归。完整输出见 tests.txt。

中间修复版6局完整四AI预验收：183场战斗，零失效跳过；当时输入哈希复核通过。逐局账本与统计在本目录。随后同时自动斩杀与复活净化修复已通过回归；最终500局在 ../v1.2-quick-500-final-20261028/ 从零运行。此前12局、中间6局与标有invalidated.json的停止批次均不混入正式500局。

239张均有独立显式效果注册及跨层绑定；无旧版效果回退。卡牌数值、研习点、库存和AI目标未因结果强弱调参。执行覆盖与数值回归不等于穷举所有组合，正式500局也不构成卡牌因果强度证明。
