# v1.2独立模拟接入检查 · 2026-10-28

结论：架构上可行，未发现必须修改v1.1 Godot客户端才能实现的规则。应建立独立的v1.2 Python模拟入口与规则模块。**当前尚不能用全部v1.2规则正常运行模拟；本检查确认接入路径，不表示已完成实现或启动验证。**

## 已完成

- 攻击强化恢复为通用普通：1费、5攻、0防，无额外效果。
- 防御强化恢复为通用普通：1费、1攻、3防，无额外效果。
- 两张都是正常卡表成员，采用普通通用8份库存；初始各发2张，初始发放不占流通库存，原有重复例外不变。
- 当前239张、通用49张；初始8张的所有卡名均存在。固定面板预算、同品质价值比及卡名唯一性检查通过。
- 按现行六类等份数、通用传奇2份、元素传奇1份、专精不入池计算，新共享池应为960份。1052份是旧252张卡表的总量，不能为维持旧总数擅自增加各卡份数。
- 本轮没有修改v1.1客户端源码、场景、Data、冻结卡库、默认牌组指针或现有战斗引擎。verify_v11再次通过。

## 正常启动的判定

1. 全239张卡都能映射到已实现且已回归的效果；显式“仅固定攻防”的基础牌单独标识。
2. 逐卡与关键交互验证：实例守恒、首次层、主副弹作用域与乘区、反应顺序、护命/复活、毒层时序、资源兑现、费用非负、私有信息边界及循环终止性。
3. 固定种子跑通少量完整四AI赛事，完成从第1轮初始构筑到最终排名的全链路，并审核库存/经济/战斗日志；不允许用异常中止、超时强行选冠军或跳过未实现牌凑成成功。
4. 上述通过后，才运行约1000场完整局的平衡测试，按第一+3、第二+1、第三−1、第四−3统计五系与15条路线。不得用启动成功证明AI策略成熟或卡牌已平衡。

本轮仅完成补牌、静态核对与接入可行性检查；未启动v1.2战斗或1000局测试。原预检报告中“初始牌缺失”已由本轮解决，其他实现缺口仍待完成。静态结果见static-audit.json，集成引用检查见integration-audit.json。
